# 提示词｜PPT 截图 → 全可编辑 PPTX

**把一张幻灯片截图复刻成「每一部分都可编辑」的演示文稿（可复用提示词 · 样例题：茶山时间轴页）**

> **怎么用这份文件**
> 1. 整份复制，直接发给另一个 DeepSeek 会话（或任何能跑代码的模型）。
> 2. 把要复刻的截图作为附件一起发；如果手上有干净底图、装饰素材，也一并附上（本包 `assets/` 内附：干净底图 `bg-photo.png`、装饰 `deco.png`、源截图）。
> 3. 若只让它做其中某个部件（例如只做时间轴），只转发第 5 节对应的 Part，并附第 9 节的参数表。
> 4. 本提示词以「茶山时间轴页」（1617×909 px）为样例，第 9 节给出该页全部实测参数。
>    换一张截图时：**方法（第 2–8 节）不动，参数（第 9 节）整体替换**，按第 10 节的空表填写。

---

## 0. 一句话任务

把附件截图（1617×909 px 的 16:9 幻灯片画面）复刻成**单页 PPTX**：视觉上与原图一致，结构上**每个元素都是 PowerPoint 里原生可编辑的对象**——文字能双击改字、形状能拖能改色、曲线能编辑顶点、图片能换图；**不允许把截图整张贴进去，也不允许把文字/线条/形状烘焙成图片**。

---

## 1. 你的角色与产出

- **角色**：PPT 逆向工程师。你擅长从一张位图反推版式参数（坐标、字号、行距、色值、图层顺序），并用 `python-pptx` 把它们重建为原生对象。
- **输入**：一张截图（必须能读到像素）；可选：干净底图、装饰素材、原字体文件。
- **产出**：
  1. `茶山时间轴页-可编辑.pptx`（单页，16:9，13.333×7.5 in）；
  2. 生成脚本 `build_ppt.py`、测量脚本、比对脚本（放在工作目录子文件夹，便于二次微调）；
  3. 一张渲染预览 PNG，以及「渲染图 vs 原截图」的差异说明；
  4. 一段交付回复：对象清单 + 每个部件的改法 + 已知差异。
- **验收口径**：文字块位置偏差 ≤ 1 px；曲线穿过三个节点圆心（≤ 1 px）；整幅并排看不出错位；**每个对象的阴影/发光与源图 4× 放大一致**（或实测确认「无」）；PPTX 里**没有任何一层是整页截图**。

## 2. 硬性规则（违反任意一条即返工）

| 编号 | 规则 | 判定方法 |
|---|---|---|
| R1 | **零整图**：不得把截图整张贴入。只允许两类位图：① 满铺照片底图（本身不含任何文字/形状）；② 抠好的装饰素材（花、叶片等）。 | 检查 `slide.shapes`，除这两张外不得有 PICTURE |
| R2 | **文字必须是真文本**：所有标题、副标题、年份、正文、艺术字都是 `add_textbox` + run；不得用图片代替，不得「文字烧进底图」。 | 逐形状 `has_text_frame`；对底图做 OCR 抽查应无字 |
| R3 | **几何必须是矢量**：时间轴是 freeform 曲线，节点是 oval，分隔线是 connector；不得用 PNG 画线。 | 形状类型检查 |
| R4 | **单位纪律**：坐标一律由像素换算成 EMU，字号一律 pt；先写换算函数，禁止手算散落在代码里。 | 代码里不出现裸数字坐标 |
| R5 | **字体替代要报备**：用系统可用字体替代原字体时，必须重新标定字号/字距，并在交付说明里写明替代关系。 | 交付说明含字体对照表 |
| R6 | **不许「看起来差不多」**：每个坐标、色值、字号都要有测量来源；测量脚本的输出要能回填到参数表。 | 参数表每行有出处 |
| R7 | **效果层必须还原**：截图里测到的阴影、发光、柔化边缘，必须用原生效果（`a:effectLst`）复现；**没测到的效果不许加**。禁止把效果烘焙进位图。 | 每个形状要么带 `effectLst`，要么在参数表里明确写「无效果」 |
| R8 | **不许自动换行**：正文按原图逐行硬换行，`word_wrap = False`，行距用固定 pt 值。 | 渲染后断行位置与原图一致 |
| R9 | **必须渲染闭环**：交付前至少渲染 1 次、与原图并排比对、记录差异、必要时改参数重渲染。 | 有 `preview/` 目录与差异清单 |
| R10 | **柔化阴影必须专测**：压缩过的截图会把阴影压成 1–2 px 的淡晕。禁止用「边缘外几像素接近白色」直接判为无阴影，必须按第 6 节的环形采样法测，并记录模糊半径、偏移、透明度、颜色。 | 效果清单里每个对象都有四项参数，或写明「实测无」 |

## 3. 坐标系、单位与换算

源截图 `1617 × 909 px`，比例 1.7789，与 16:9（1.7778）差 0.06%，**按 16:9 归化，不裁边**。

| 量 | 值 | 说明 |
|---|---|---|
| 画布 | 13.333 × 7.5 in = 960 × 540 pt | `prs.slide_width = 12192000`，`prs.slide_height = 6858000` |
| 横向量 | 12192000 / 1617 = **7539.64 EMU/px** | x、宽、左偏移用它 |
| 纵向量 | 6858000 / 909 = **7544.00 EMU/px** | y、高、上偏移用它 |
| 字号量 | 540 / 909 = **0.5937 pt/px** | 字号、字距、行距用它 |

> ⚠️ 最容易犯的错：用 96 dpi 的 `1 px = 0.75 pt` 换算，全部字号会大 26%。**只认 0.5937**。

```python
from pptx.util import Emu
EMU_W, EMU_H = 12192000, 6858000
W, H = 1617.0, 909.0
SX, SY = EMU_W / W, EMU_H / H      # 7539.64, 7544.0
PT = 540.0 / H                      # 0.5937 pt/px

def ex(px): return Emu(int(round(px * SX)))
def ey(px): return Emu(int(round(px * SY)))
def pt(px): return px * PT          # 12 px -> 7.12 pt
```

**坐标语义**：所有文本框坐标写的是**文本框左上角**，不是字形墨迹左上角。两者相差 4–18 px（行框上留白），这是正常的，**不要为了对齐墨迹而手动上移文本框**；渲染比对时按墨迹复核。

## 4. 图层与对象清单（先定结构，再写代码）

自下而上 6 层；只有两处真实遮挡：**节点压曲线**、**装饰素材压标题**。

| z | 层 | 对象类型 | 数量 | 效果（阴影/发光） | 可编辑性 |
|---|---|---|---|---|---|
| 1 | 底图 | `add_picture` 满铺 | 1 | 无 | 可换同尺寸图 |
| 2 | 时间轴曲线 | freeform（无填充，4 pt 渐变线） | 1 | 无 | 可编辑顶点 |
| 3 | 节点 | `MSO_SHAPE.OVAL`（白填充 + 有色环） | 3 | 无 | 可改大小/颜色 |
| 4 | 分隔线 | connector（1 pt，白 75%） | 3 | 无 | 可拖端点 |
| 5 | 文字块 | textbox（标题/副标题/年份/正文） | 12 | 无 | 完全可编辑 |
| 6 | 标题艺术字 + 英文 | textbox（单字/两行） | 3 | 无 | 完全可编辑 |
| 7 | 装饰素材 | `add_picture`（带 alpha） | 1 | 无 | 可整体替换 |

**样例页实测文件共 24 个形状**：2 张图片 + 1 条 freeform + 3 个椭圆 + 3 条直线 + 15 个文本框（12 个常规文字 + 3 个标题）。

> **「效果」列不能空着**：这是偷懒和翻车的高发区。逐个对象判断「有阴影/发光/柔化边缘吗」——
> 有，就把模糊、偏移、透明度、颜色写进第 5 节 Part H；
> 没有，就明确写「无」，别留白。写「无」之后才允许给形状 `shadow.inherit = False`。

> 先把这个清单写成表，再逐行实现。顺序就是 z-order——**python-pptx 后加的在上层**，所以必须按 1→7 添加；发现压错层，用 `spTree` 调整节点顺序，不要靠改坐标掩盖。

## 5. 分部件施工说明

> 每个部件都按「长什么样 → 参数 → 怎么做 → 坑 → 验收」写。实现全部用 `python-pptx`（1.0.2 及以上）+ 必要的手写 DrawingML。

### 公共工具：文本渐变与渐变描边

`python-pptx` 不支持「文字渐变」「线条渐变」，需要手写 XML：

```python
from lxml import etree
from pptx.oxml.ns import qn
NS = 'http://schemas.openxmlformats.org/drawingml/2006/main'

def grad(stops, ang=0):
    gs = ''.join('<a:gs pos="%d"><a:srgbClr val="%s"/></a:gs>'
                 % (int(p * 1000), c) for p, c in stops)
    return ('<a:gradFill xmlns:a="%s" rotWithShape="1"><a:gsLst>%s</a:gsLst>'
            '<a:lin ang="%d" scaled="1"/></a:gradFill>'
            % (NS, gs, int(ang * 60000)))

def set_grad_line(shape, stops, width_pt, ang=0):
    ln = shape.line._get_or_add_ln()
    for c in list(ln): ln.remove(c)
    ln.set('w', str(int(width_pt * 12700)))
    ln.set('cap', 'rnd')
    ln.append(etree.fromstring(grad(stops, ang)))
    ln.append(etree.fromstring('<a:round xmlns:a="%s"/>' % NS))

def set_grad_text(run, stops, ang=0):
    rPr = run._r.get_or_add_rPr()
    for tag in ('solidFill', 'noFill', 'gradFill'):
        for c in rPr.findall(qn('a:' + tag)): rPr.remove(c)
    rPr.insert(0, etree.fromstring(grad(stops, ang)))   # 必须插在 rPr 首位
```

文本用渐变时：**不要再设 `run.font.color`**（会被覆盖或冲突）；同时给 run 加 `<a:ea typeface="字体名"/>`，保证中文命中同一字体。

### 公共工具：文本框（本页所有文字同一套参数）

```python
def textbox(slide, lines, x, y, width, size, bold=False, pitch=None,
            spc=0.0, grad_stops=None, font='Microsoft YaHei',
            align=PP_ALIGN.LEFT):
    box = slide.shapes.add_textbox(ex(x), ey(y), ex(width), ey(10))
    tf = box.text_frame
    tf.word_wrap = False          # 不自动换行
    tf.auto_size = None           # 不自动缩放
    tf.margin_left = tf.margin_right = tf.margin_top = tf.margin_bottom = 0
    tf.vertical_anchor = MSO_ANCHOR.TOP
    for i, line in enumerate(lines):
        p = tf.paragraphs[0] if i == 0 else tf.add_paragraph()
        p.alignment = align
        p.space_before = Pt(0); p.space_after = Pt(0)
        if pitch: p.line_spacing = Pt(pitch)     # 固定行距（pt）
        r = p.add_run(); r.text = line
        f = r.font; f.name = font; f.size = Pt(size); f.bold = bold
        f.color.rgb = RGBColor(0xFF, 0xFF, 0xFF)
        rPr = r._r.get_or_add_rPr()
        if spc: rPr.set('spc', str(int(round(spc * 100))))   # 字距，单位 1/100 pt
        ea = etree.SubElement(rPr, qn('a:ea')); ea.set('typeface', font)
        if grad_stops: set_grad_text(r, grad_stops, ang=0)
    return box
```

> 框高写 `10 px`（≈ 5.9 pt）即可：不自动缩放、不换行、顶端锚定，文字会自然溢出显示，且**框顶 = 首行行框顶**，位置可控。**不要**给框设固定高度去「包住」文字，那会引入居中偏移。

### Part A｜背景照片层（满铺位图）

**长什么样**：一张茶山梯田俯拍照片，已压暗；标题区没有字；右下沿一条曲线再压暗 30%。照片本身**不含任何字形、不含时间轴**。

**参数（样例页）**

| 项 | 值 |
|---|---|
| 位置 | (0, 0)，尺寸 12192000 × 6858000 EMU（满铺） |
| 素材 | `bg-photo.png`，1617 × 909，无 alpha |
| 整体压暗 | 亮度 −40%（烘焙进位图，**不要在 PPT 里叠半透明黑**） |
| 曲线以下压暗 | ×0.70（30% 黑），边界 = 时间轴中心线 y(x) |
| 逐行亮度 | 与源图对齐，垂直增益 1.25（顶）→ 0.60（底） |

**怎么做**

1. 若用户给了 `bg-photo.png`：直接 `add_picture(BG, 0, 0, Emu(EMU_W), Emu(EMU_H))`。
2. 若只有截图：**不要在原截图上补绘标题区**（会留下灰雾或拼贴缝）。改用一张同题材高清茶山照片重建：
   - 裁切/缩放到 1617×909；
   - 对「纯照片区」逐通道做线性拟合（样例：R 0.622/+4.8，G 0.626/+5.2，B 0.392/+3.8）；
   - 整幅 ×0.6（对应 −40% 亮度），曲线以下再 ×0.70；
   - 用逐行亮度比做二次拟合，得到 1.25→0.60 的垂直增益，把上暗下亮对齐原图。
3. 保存为 RGB PNG（**不要带 alpha**，避免 PDF 里走 SMask 出现 1 px 细边）。

**坑**

- 底图里残留任何书法笔画 → 编辑艺术字时会露馅。**底图必须是「无字形」的。**
- **照片层里的字不止标题**：页面标题、水印、页码、角标，只要出现在照片/底图上，都必须擦掉再上真文本。否则真文本一盖上，会变成「两层字」——因为两层几乎重合，正面看不出来，放大或改字才露馅（第 14 节第二个案例）。
- 在 PPT 里再叠一层 30% 黑 → 不同渲染器 gamma 不同，整体偏暗 3–5 级；压暗只能烘焙。
- 底图带 alpha → LibreOffice 转 PDF 时被重编码，边缘出现细边。
- **先想清楚这张图是怎么做的**：是「照片」，还是「照片 + 蒙版（白雾/渐变/羽化）」？把图层拆出来再决定实现：
  - 卡片把周围衬得更淡、自己更艳，往往是「背景照片 + 白色蒙版开洞」，不是「卡片带半透明白底」；
  - 若蒙版是**纯色恒定透明度**，可以用形状复现；若蒙版**带渐变/羽化**（常见：底部渐隐），用多个半透明形状拼会在边缝处露馅，**把蒙版烘焙进照片**更稳；
  - 反解蒙版（`P = (O − 255a) / (1 − a)`）会把压缩噪声放大 1/(1−a) 倍（a=0.7 时 3.3 倍），反解图只能当参考，不要直接当底图；
  - 不同渲染器对半透明/渐变 alpha 的合成不完全一致（同一份 XML，PDF 里可能整体亮/暗 5–10 级），凡是「多层半透明叠出来」的效果，优先烘焙，只在**必须可编辑**时才用形状。
- **洞的边界要按像素阶跃找，不要按卡片的视觉轮廓找**：蒙版常常会盖住卡片的下半段。本例三张卡片的视觉底边在 y≈573，但内像素在 **y=540** 从深水（58,106,128）一步跳到蒙版色（198,212,218）——那才是洞的真实底边；570 附近那条浅色只是「蒙版覆盖区」，不是卡片内容。
  - 做法：沿卡片中线取 `y` 方向的像素序列，找**单行幅度 > 60 级**的跳变（开洞 → 蒙版）；找不到跳变才说明洞到底；
  - 洞的高宽各让 1 px：本例洞 = (135,107)–(335,540)，若按视觉底边 574 开洞，下半部会出现一条「鲜色带」——这是最容易犯的错。

**验收**：`slide.shapes` 里第一张就是 PICTURE，尺寸等于画布；**对每张照片层跑一次 OCR（或 2× 目视逐块扫），结果必须为 0 个字**；再放大看每个文字块背后，不能有第二层字的淡影。

### Part B｜主标题艺术字「将 / 来」+「Our Future」

**长什么样**：书法体两字错落排布：「将」在上偏左，「来」在下偏右、压住「将」的右下；颜色是绿→黄绿渐变；两字右上压一朵白茉莉与几片叶（Part C）。**必须是文本**，不能是图片。

**参数（样例页）**

| 项 | 将 | 来 |
|---|---|---|
| 字体 | 华文行楷 | 华文行楷 |
| 字号 | 110 pt | 110 pt |
| 字距 | −2.0 pt | −2.0 pt |
| 渐变 | 0% `0F883F` → 100% `4DBC45` | 0% `7DBE44` → 100% `DDE22E` |
| 墨迹左上（实测） | (694, 60) | (806, 134) |
| 墨迹相对框原点 | (0.1108, 0.2719) em | (0.1913, 0.2366) em |
| 墨迹占 em | 0.770 × 0.886 | 0.750 × 0.921 |
| 文本框（算得） | (673.5, 9.7) | (770.6, 90.2) |
| 框宽 | 1.7 em | 1.7 em |

> em = 字号 / 0.5937 ≈ 185 px（110 pt）。**按墨迹定位，反算框位置**：
> `box_x = ink_x − rel_dx × em`，`box_y = ink_y − rel_dy × em`。
> 换字号不用重测（度量按 em 归一化）；**换字体必须重测**。

**怎么做**

1. 先渲染一张白底测试图，量出每个字的 `ink_dx/ink_dy/rel_dx/rel_dy`（见第 6 节量法），存 JSON。
2. 每个字**单独一个文本框**，`textbox(..., [ch], box_x, box_y, width=1.7*em, size, spc=-2.0, grad_stops=[...])`。
3. 两字 z-order 按「将」在下、「来」在上（来压住将的右下）。
4. 英文「Our / Future」：Bodoni MT 16 pt，两段、居中，框 (690, 240)，行距 20.2 pt，白色。

**坑**

- 千万别把两字并排摆一个框：错位 74 px 是设计的一部分。
- 艺术字不要加粗、不要描边（字重一变，渐变就糊）。
- 字体不可得时（华文行楷缺失）：换成另一款行楷/书法字体，并**重新测 em 度量**；不允许把艺术字转成图片。
- 「来」的框比字大很多是正常的：框宽 1.7 em，字只占 0.75 em。

**验收**：两个 TEXT_BOX，各 1 个字符，`font.name = 华文行楷`，run 上有 `gradFill`；渲染后墨迹起点误差 ≤ 1 px；「来」比「将」低约 74 px。

### Part H｜效果层（阴影 / 发光 / 柔化边缘）

**长什么样**：很多模板会给圆、卡片、序号块加一层柔和的投影——光源在上方，阴影落在下侧、略带模糊，浓度通常只有 15%–40%。这种效果在压缩截图里**极易被吃掉**，只留下 1–2 px 的淡晕（详见第 14 节复盘）。

**第一步永远是「有没有」**：不要看整图，要放大到 4–8 倍看对象下缘。判断标准不是「外面是不是白」，而是「外面有没有一层**有方向的灰度渐变**」：

- 阴影一定**不对称**：下侧比上侧暗、右下比左上暗；四边一样淡的是压缩振铃。
- 阴影一定是**灰的**（或同色系深色），不是纯白；纯黄晕多半是 JPEG 色度下采样。
- 阴影会**跳过被遮挡的部分**：被文字、别的形状盖住的地方没有影子。

**检测法（写进 `measure.py`，每个形状跑一遍）**

1. 取形状外接框，按中心与半径（或四条边的法线）在**外部 1–20 px** 环形采样。
2. 换算成「与背景的差值」：`d = 255 − min(R,G,B)`，再做 6–10 倍对比拉伸存一张可视化解码图。
3. 按方位分桶（上/下/左/右、四个斜角），看均值差：
   - 下侧均值差比上侧高 3 级以上 → 有向下阴影；
   - 各方向都在 1–2 级、且随半径快速归零 → 判为压缩噪点，记「无效果」。
4. 有阴影时估三个参数：
   - **偏移**：下侧差值峰值离边缘的距离；
   - **模糊**：差值从峰值衰减到 10% 的径向宽度（约等于 `blurRad`）；
   - **透明度**：`α ≈ 峰值差 ÷ (255 − 背景亮度)`，再按颜色反推。
5. 记进参数表：`对象 | 颜色 | 模糊(px) | 偏移(px) | 方向(°) | 透明度`。

**怎么写进 PPTX**（`python-pptx` 没有阴影 API，手写 `a:effectLst`；必须放在 `spPr` 里、`a:ln` 之后）

```python
from lxml import etree
from pptx.oxml.ns import qn

def set_shadow(shape, blur_px, dist_px, dir_deg, color='000000', alpha=35.0):
    """blur/dist 用设计稿像素，换算成 EMU；dir 单位是 1/60000 度。"""
    spPr = shape._element.spPr
    for e in spPr.findall(qn('a:effectLst')):
        spPr.remove(e)                      # 先清掉空 effectLst，避免重复
    xml = ('<a:effectLst xmlns:a="http://schemas.openxmlformats.org/drawingml/2006/main">'
           '<a:outerShdw blurRad="%d" dist="%d" dir="%d" algn="ctr" rotWithShape="0">'
           '<a:srgbClr val="%s"><a:alpha val="%d"/></a:srgbClr>'
           '</a:outerShdw></a:effectLst>'
           % (int(round(blur_px * SX)), int(round(dist_px * SX)),
              int(round(dir_deg * 60000)), color, int(round(alpha * 1000))))
    spPr.append(etree.fromstring(xml))
```

> `SX` 是本页的「EMU / px」。向下 = 90°，向右 = 0°。`algn="ctr"`、`rotWithShape="0"` 照抄，否则旋转/对齐会变形。

**参数模板**

| 对象类型 | 模糊 | 偏移 | 方向 | 透明度 | 备注 |
|---|---|---|---|---|---|
| 大色块/大圆（100–200 px） | 12–16 px | 4–6 px | 90° | 15%–25% | 越大越软，否则像描边 |
| 小圆点/序号（40–60 px） | 6–8 px | 2–3 px | 90° | 30%–40% | 收紧一点才像实体 |
| 卡片/图片 | 10–14 px | 3–5 px | 90° | 20%–30% | 有描边时阴影从描边外算 |

**本任务实例（当前趋势页，5 个圆全部带阴影）**

| 对象 | 直径 | 模糊 | 偏移 | 方向 | 透明度 |
|---|---|---|---|---|---|
| 左上淡黄大圆 | 169 px | 14 px | 5 px | 90° | 20% |
| 「势」后粉圆 | 40 px | 6 px | 2.5 px | 90° | 35% |
| 01 / 02 / 03 | 48 px | 7 px | 3 px | 90° | 35% |

**坑**

- **最常犯：把淡晕当压缩噪点**。判据见第 14 节：只要下侧比上侧系统性高 3 级以上，就是阴影，不是噪点。
- 只给一部分对象加：同一页的光源必须一致（都是向下、同一色系），否则像拼贴。
- 阴影烘焙进位图：用户没法改，换图后阴影还在。必须走 `effectLst`。
- 把阴影加在文字块上：文字通常没有阴影；给文字加阴影会让字发糊，先确认再动。
- 用 `shadow.inherit = False` 之后忘了加 `effectLst`：等于主动删掉效果。

**验收**：把对象下缘裁出来放大 4×，与源图并排——方向、偏移、软硬、浓度四项都要对得上；参数表里有四项数值。

## 6. 测量方法（禁止肉眼估）

| 要测什么 | 怎么测 |
|---|---|
| 画布 | `PIL.Image.open(...).size`；比例与 16:9 差 > 1% 才裁边，否则拉伸 0.06% |
| 色值 | 指定坐标 5×5 中位数；文字色取 top-40 均值；渐变沿方向取 ≥ 3 点 |
| 字号 | 量字形墨迹高（CJK 字面高 ≈ 0.89 em；数字 ≈ 0.72 em），再 `pt = 墨迹高 × 0.5937 ÷ 0.89`，最后用渲染比对微调 |
| 文本框坐标 vs 墨迹 | 两者都记：框坐标给执行，墨迹坐标给复核（差 4–18 px 正常） |
| 字距 | `(首字墨迹左 → 末字墨迹右) − 单字宽 × (n−1)`，多行取平均 |
| 行距 | 相邻两行同字墨迹底的 y 差；多行取中位数 |
| 曲线 | 逐列找绿色像素的中位 y，每 10 px 一点；先剔除节点 ±30 px 内的点，再插值 + 三点平滑 |
| 圆 | 找亮核/彩环的外接框：几何直径 = 外径 − 线宽（线宽 = 27 − 21.5 ≈ 5.5 px） |
| 分隔线 | 行/列亮度突变，取长度与 y；透明度由叠加后的亮度反推（208/195/169 → 75%） |
| 透明装饰 | 与干净底图做差分 → matte；连通域面积阈值剔除文字块 |
| 阴影/发光 | 外接框外 1–20 px 环形采样，按方位分桶比较与背景的差值；下侧比上侧高 3 级以上即为阴影（详见 Part H） |
| 效果参数 | 偏移 = 差值峰值到边缘的距离；模糊 = 峰值衰减到 10% 的径向宽度；透明度 = 峰值差 ÷（255 − 背景亮度） |
| 照片层残字 | 对每张位图跑 OCR；再用 2× 目视逐块扫（标题、水印、角标最容易漏）；擦字后原地放大复查 |

**原则**：每个数字都要能回填到参数表，并注明测量方式。宁可写「待测」，不要写「约」。

## 14. 复盘：阴影为什么会被漏掉（本提示词的自我修正记录）

> 这一节是真实踩坑记录，用来说明前面几条规则为什么存在。照着做可以避免同一个坑。

**现象**：用户发来一张「当前趋势」截图（1116×627，PNG，531 KB），页面上 01/02/03 三个序号圆、左上淡黄大圆、「势」后粉圆**都带柔和投影**。第一版成品只还原了几何、文字、颜色，五个圆的阴影一个都没做出来。

**根因（按贡献排序）**

1. **提示词自己写反了**。旧版 R7 是「不许加效果：不加阴影、发光、柔化边缘」。它本意是防「臆造效果」，但字面上把「还原测量到的效果」也一起禁了。执行方严格照做，反而漏掉真实效果。→ 已改为 R7「效果层必须还原：测到的必须复现，没测到的不许加」。
2. **测量项里没有「效果」**。第 6 节的表只覆盖画布、色值、字号、字距、行距、曲线、圆、分隔线、抠图，没有阴影；参数清单也没有「效果」列。没有测量项，就不会被发现。
3. **判据太粗**。当时的判断是「圆外 2 px 是纯白 → 无阴影」。而这张图经过降采样 + JPEG 4:2:0，柔化阴影被平均成 1–2 px 的淡晕：02 正下方 y=224 还是 RGB(255,239,139)，y=226 就回到纯白；再往外 20 px 全是 255。用「2 px 白不白」判，必然误判成无阴影。
4. **黄晕伪装成噪点**。黄圆在白底上压缩后，边缘本来就有黄色色度溢出。阴影（灰）与色度溢出（黄）混在一起，肉眼与阈值都容易归成「压缩振铃」。
5. **验收指标不敏感**。整幅 MAE 6.48/255、超 30 级像素 5.45%，看上去「很合格」；但细阴影只覆盖每圆外侧一圈、总像素不到千分之几，对 MAE 的贡献 < 0.2。**MAE 合格 ≠ 效果还原。**
6. **默认值偏见**。白底页容易让人默认「没有效果」，而阴影恰恰是这种页最容易被忽略的一层。

**修正（已经写进前文）**

| 位置 | 改了什么 |
|---|---|
| §2 R7 / R10 | 效果从「禁止」改为「必须还原 + 必须专测」 |
| §4 对象清单 | 增加「效果」列，逐个对象填「有/无」，不许留白 |
| §5 Part H | 新增效果层：检测法、参数模板、`outerShdw` 代码、本任务实例 |
| §6 测量表 | 增加「阴影/发光」「效果参数」两行（环形采样法） |
| §8 验收 | 增加「效果核对：方向/偏移/软硬/浓度 4× 放大一致」 |
| §9 速查 | 补充「有阴影」样例与「无效果」样例的对照 |
| §10 模板 | 增加「效果」填写行 |
| §12 负向清单 | 增加「把阴影当噪点」「只加一部分」「烘焙阴影」「用 MAE 掩盖」「带字截图当背景」 |

**30 秒自检（交付前必做）**

对每个圆形/卡片/色块，把下缘裁出来放大 4×，并排源图看三件事：

1. 阴影方向对不对（应朝下、右下更重）；
2. 软硬对不对（大对象更软，小对象更紧）；
3. 浓度对不对（不能没有，也不能重到发脏）。

三件事都过，才算这一层还原完成；只要有一项不对，就回到 Part H 重新量参数。

### 第二个案例：「目录」页的标题叠影（照片层没擦字）

**现象**：另一页「目录」（卡片式排版）复刻时，几何、竖排字、序号都对齐了，但左上角标题看起来比原图「更粗、更脏」。放大 4× 才发现：背景照片里本来就有「目录 /Contents」，我又在上面盖了一层真文本，两层字错开 1–2 px，叠成了双层描边。

**根因**：擦字只做了卡片里的标题（因为卡片要重画背景），**漏了直接压在照片上的页面标题**。它不像卡片那样有明确的「窗口」边界，很容易被当成背景的一部分。

**修正**：把标题所在的整块矩形区域填平（按上下边缘做垂直渐变 + 6 px 羽化），再叠真文本；背景图里从此没有任何字形。

**通用化后的规则**（已写进 Part A 坑、§6、§8、§12）：

1. 只要一张位图代表「背景/照片」，它就必须**零字形**——包括标题、水印、页码、角标，不只是被覆盖的卡片区域。
2. 擦字后要在**原位置放大 4×** 看：擦掉的字不能留下浅色字影，也不能因为填充而出现矩形接缝（填充边缘要羽化）。
3. 交付前对每张位图跑 OCR：结果必须是 0 个字。这一条比 MAE 更能抓住「叠影」问题。
4. 双层字常常「正面看不出来」：因为两层几乎重合，只有放大、换字号或移动文本框时才暴露。**不要等到用户发现。**
